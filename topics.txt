That's okay, Amal. 👍 This is a slightly more advanced theory question. Many beginners know how to use Hooks before knowing why they were introduced.

Let's learn the interview answer.

Why do we need Hooks?

Before Hooks, React mainly used class components to manage:

State
Lifecycle methods
Side effects

Example (old style):

class Counter extends React.Component {
  constructor() {
    super();
    this.state = {
      count: 0
    };
  }

  render() {
    return (
      <h1>{this.state.count}</h1>
    );
  }
}

The problem was:

1. Functional components could not have state

Before Hooks:

function Counter() {
  return <h1>0</h1>;
}

A functional component was only used for displaying UI.

It could not use:

State
Lifecycle methods
2. Class components became complicated

Large class components had:

Lots of lifecycle methods
Duplicate logic
Complex this handling

Example:

componentDidMount()
        ↓
componentDidUpdate()
        ↓
componentWillUnmount()

Managing related logic became difficult.

Hooks solved this.

Hooks allow functional components to use React features.

Examples:

useState

Gives state:

const [count, setCount] = useState(0);
useEffect

Handles lifecycle and side effects:

useEffect(() => {
  console.log("Mounted");
}, []);
useRef

Stores values and accesses DOM:

const inputRef = useRef(null);
Interview answer:

"Hooks were introduced to allow functional components to use features like state and lifecycle methods. Before Hooks, these features were mainly available in class components. Hooks made functional components more powerful, reduced complexity, and allowed developers to reuse stateful logic more easily."

Don't worry that you didn't know this. In your learning plan, this comes after understanding lifecycle and before deep useEffect.
