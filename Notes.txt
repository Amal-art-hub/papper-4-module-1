
Single Page Applications (SPA)

A Single Page Application (SPA) is a web application that loads a single HTML page initially. After that, when the user navigates between 
different sections or pages, only the required content is updated without reloading the entire webpage. This makes the application faster 
and provides a smoother user experience. React is commonly used to build SPAs




What is React?
React is a JavaScript library developed by Facebook for building user interfaces. It uses a component-based architecture, allowing 
developers to create reusable UI components. React updates only the parts of the page that change, making web applications fast and 
efficient.

Why was React created?
React was created because managing dynamic and complex user interfaces with plain JavaScript became difficult as applications grew larger.
 It simplified UI development by introducing reusable components and efficient rendering.

What problems does React solve?
React solves problems such as inefficient UI updates, code duplication, and difficulty maintaining large applications. It improves 
performance by updating only the changed parts of the page and makes development easier through reusable components and a structured 
architecture

Advantages of SPAs
1. Faster Navigation

After the initial load, moving between pages is very fast because only the necessary data is updated.

2. Better User Experience

No full-page refresh means the app feels smooth, similar to a desktop or mobile application.

3. Less Server Load

The server usually sends data (often as JSON) instead of generating a completely new HTML page for every navigation.

4. Efficient Updates

Only the parts of the UI that change are updated, reducing unnecessary rendering.

5. Easier to Build Interactive Applications

SPAs are well-suited for applications with frequent user interactions, such as dashboards, chat apps, and social media platforms.

Disadvantages of SPAs
1. Slower Initial Load

The browser downloads the application's JavaScript bundle when the app first loads, which can make the initial page load slower.

2. SEO Challenges

Search engines may have more difficulty indexing content that is rendered entirely in the browser, although modern frameworks and rendering techniques (like server-side rendering) can address this.

3. JavaScript Dependency

If JavaScript is disabled or fails to load, the application may not function correctly.

4. Browser Memory Usage

Large SPAs can consume more browser memory because much of the application remains loaded.






A Single Page Application, or SPA, is a web application that loads a single HTML page initially and dynamically updates only the required 
parts of the page without reloading the entire page. This provides faster navigation and a smoother user experience. React helps build 
SPAs by dividing the UI into reusable components and updating only the components that change. Examples of SPAs include Gmail, Facebook, 
Instagram, and WhatsApp Web





1. What is Client-Side Rendering (CSR)?

Client-Side Rendering (CSR) is a rendering technique where the browser creates the user interface. When a user opens a React application, 
the server sends a basic HTML file along with JavaScript and CSS files. The browser executes the JavaScript, and React dynamically 
generates and updates the HTML in the browser. This allows fast navigation and a smooth user experience without reloading the entire 
page



2. What is Server-Side Rendering (SSR)?

Server-Side Rendering (SSR) is a rendering technique where the server generates the complete HTML page before sending it to the browser. 
The browser receives a ready-to-display HTML page, so the initial page load is faster and search engines can easily index the content






Interview Follow-up: Difference Between CSR and SSR

In Client-Side Rendering, the browser creates the UI by executing JavaScript, whereas in Server-Side Rendering, the server generates the 
complete HTML before sending it to the browser. CSR provides a smoother and faster user experience after the initial load, making it 
ideal for interactive applications. SSR offers a faster initial page load and better SEO because the browser receives a fully rendered

Why do we use JSX?

We use JSX because it makes React code easier to write, read, and understand. JSX allows us to write HTML-like syntax inside JavaScript, 
which makes building user interfaces more intuitive. Although it looks like HTML, it is actually converted into React.createElement() 
calls during compilation. JSX is not mandatory, but it is the standard way of writing React components because it improves code 
readability and developer productivity



Is JSX HTML?

No, JSX is not HTML. JSX looks similar to HTML, but it is a syntax extension of JavaScript. It allows developers to write HTML-like 
syntax inside JavaScript, but it follows JavaScript rule


Why do we use className instead of class?


We use className instead of class in JSX because JSX is written inside JavaScript, and class is a reserved keyword in JavaScript used for 
creating classes. To avoid conflicts, React uses className to define CSS classes



What is a component?

A component is a reusable and independent piece of the user interface. It is usually a JavaScript function that returns JSX, and multiple 
components can be combined to build a complete React application.


. Why are components reusable?

Components are reusable because they are written once and can be used multiple times in different parts of an application. This reduces 
code duplication, makes maintenance easier, and keeps the code organized




Difference between functional and class components?

A functional component is a JavaScript function that returns JSX and is the preferred approach in modern React. A class component is an 
ES6 class that extends React.Component and uses a render() method. Today, functional components are preferred because they are simpler 
and support Hooks




What are props?

Props (Properties) are used to pass data from a parent component to a child component. They are read-only and help make components 
reusable


. Can a child modify props?

No. Props are read-only. A child component can only receive and use props. Only the parent component can change the values of

  What is State?

State is a built-in React feature used to store data that belongs to a component and can change over time. When the state changes, React automatically re-renders the component 
to update the UI.

Why do we need State?

We need state to manage dynamic data such as counters, form inputs, toggles, and other values that change during the application's lifecycle.

What problem does State solve?

State solves the problem of keeping the UI synchronized with changing data. When state changes, React automatically updates the displayed UI without manually manipulating the 
DOM

State is data that is managed within a React component and can change during the component's lifetime. When state changes, React automatically re-renders the component to 
reflect the updated data in the UI. We use state to handle dynamic data like counters, forms, toggles, and user interactions

Q1: What causes React to re-render?

Answer:

A React component re-renders when its state changes, when its props change, or when its parent component re-renders. React re-renders the component to calculate the updated UI.

Q2: Does changing a normal variable trigger a re-render?

Answer:

No, changing a normal variable does not trigger a re-render because React does not track normal variables. React only tracks changes made through state setters or changes in props.

Q3: What happens when state changes?

Answer:

When state changes, React schedules a re-render of the component. The component function runs again with the updated state, React compares the new output with the previous 
output, and updates the necessary DOM elements.




1. How do you handle events in React?

Answer:

Events in React are handled by attaching event handlers to JSX elements using camelCase event names such as onClick, onChange, and onSubmit. When the event occurs, the 
associated function is executed.



In HTML, event names are lowercase and event handlers are often written as strings. In React, event names use camelCase, and we pass JavaScript function references instead of 
strings. React also wraps browser events in a Synthetic Event object to provide consistent behavior across different browsers.
